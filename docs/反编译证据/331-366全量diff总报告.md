# TB710FU 331 vs 366 HDR 支持全量 diff — 总报告

- 日期：2026-08-31
- 对象：`TB710_ZUXOS_1.1.04.331` vs `TB710_ZUXOS_1.5.04.366_Tool` 救砖包（super 动态分区 + dtbo）
- 症状基线：升级后 `DisplayInfo.hdrSdrRatio` 恒 NaN → UltraHDR 图片不提亮（酷安/相册）；HDR 视频（DV/HLG/PQ）正常
- 子报告：`分析-servicesjar-diff.md`（门③实锤）、`分析-native-sfdiff.md`（native 无罪）、`分析-zui私改-diff.md`（ZUI 门控链）

## 一、必须纠正的前提

**331 是 Android 15**（`ro.system.build.version.release=15`，AQ3A.250129.001，构建 2025-09-25），**366 是 Android 16**（BP2A.250605.031.A3，构建 2025-12-23）。
所以这不是一次普通的联想小版本回归，而是 **A15→A16 大版本迁移**——HDR 断链的主体是 AOSP 16 上游新增的门，联想在 rebase 时知情并自留了后门（见下）。

## 三、根因链（完整版）

```
A16 上游在 LocalDisplayAdapter.handleHdrSdrNitsChanged 加了门③
  （ratio 仅在 SurfaceControl 亮度通道开启时计算: mUseSurfaceControlBrightness
    = SF hasDisplayCapability(BRIGHTNESS)，或 mForceSurfaceControl）
        ×
TB710FU 的 QTI vendor HWC 是 A15 时代老件，从未声明 DisplayCapability.BRIGHTNESS
（366 一字未改 → 升级后按 A16 新规矩它"不合格"）
        ⇒ 门③恒 false ⇒ mCurrentHdrSdrRatio 恒 NaN ⇒ HWUI gainmap W=0 ⇒ 图片不提亮
        （HDR 视频走 HWC device composition 不经 ratio ⇒ 视频正常，症状自洽）
        +
ZUI 1.5 另加自家 HBM/屏幕增强门（默认关）——即使门③过，第二道也会把提亮钳制
联想知情证据: 366 services.jar 内置 is_test_mode 后门 + 新增 getHighestHdrSdrRatio API
  （CTS 16 要求 ratio 可用，联想用后门应付测试, 用户侧未暴露任何开关）
```

## 五、实机验证清单（按顺序）

```sh
# 0) 基线
su -c 'dumpsys display | grep -iE "hdrSdrRatio|HighestHdrSdrRatio"'
su -c 'cmd display 2>/dev/null; dumpsys SurfaceFlinger | grep -i brightness | head -5'
# 1) ZUI 开关试探（每项做完看酷安图片）
su -c 'settings put system zui_screen_enhance_enabled 1'

# 看看显示菜单里是否出现“屏幕增强”
# 2) 门③确认（诊断联想后门是否可行）
su -c 'setprop persist.sys.lenovo.is_test_mode true; settings put system screen_brightness $(expr $(settings get system screen_brightness) + 1)'
su -c 'dumpsys display | grep -i hdrSdrRatio'   # 出数值(非NaN) => 门③确诊 & 后门有效
su -c 'setprop persist.sys.lenovo.is_test_mode false'  # 诊断完务必关回！
# 3) LSPosed v2 模块主验证
#    启用 com.tb710fu.hdrfix -> 重启 -> 酷安右侧栏图片明显变亮 = 修成
#    再确认: su -c 'dumpsys display | grep hdrSdrRatio' 应显示 4.0（模块填充值）
```
