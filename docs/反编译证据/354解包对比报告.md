## 三、6 个问题答案

### 1）354 的 handleHdrSdrNitsChanged 有没有 366 那种门控？——**没有（预期证实）**

354（与 331 逐字节一致）的实现位于 `LocalDisplayAdapter$LocalDisplayDevice$1.smali`（Runnable 匿名类）：

```
handleHdrSdrNitsChanged(hdrNits, sdrNits):
    if hdrNits == -1 || sdrNits == -1:  ratio = NaN
    else:                               ratio = max(1.0f, hdrNits/sdrNits)
    if !BrightnessSynchronizer.floatEquals(mCurrentHdrSdrRatio, ratio):
        mCurrentHdrSdrRatio = ratio;  updateDeviceInfoLocked()
```

整个方法只有 "-1 → NaN" 和 "比值" 两条路径，**不存在** 366 的
`mUseSurfaceControlBrightness || mForceSurfaceControl` 第三条门（该门在 366 的
`setDisplayBrightness` → `handleHdrSdrNitsChanged` 调用点之间，354 全文件 grep 无此字段参与该链）。
`mUseSurfaceControlBrightness` 在 354/331 只存在于 `BacklightAdapter` 内部（背光通道选择），与 HDR 比值无关。

### 2）354 的 hasSdrToHdrRatioSpline 读哪个字段？——**与 331 相同，读顶层 mSdrToHdrRatioSpline**

`DisplayDeviceConfig.hasSdrToHdrRatioSpline()Z`（354=331 逐字节一致）：
`iget mSdrToHdrRatioSpline; if-eqz → false`。
顶层 spline 由 A15 上游 `loadHighBrightnessModeData(DisplayConfiguration)` 从标准 displayconfig XML 的
highBrightnessMode 节点填充（L4687 `iput mSdrToHdrRatioSpline`）。
联想私有的 `zuiLoadHighBrightnessModeData()`（读 `system/etc/display_hdr.xml`，`initFromGlobalXml()` 尾部调用）
只填新字段 `mHdrBrightnessData`（initFromFile 中 iput），**不动顶层 spline**。
366 才把读取点改成 `mHbmData.sdrToHdrRatioSpline`（A16 上游重构）——354 无此问题。

### 3）354 有没有 HdrBrightnessModifier？——**没有 → 确认它是 366（A16）新增**

354 与 331 的 `brightness/clamper/` 均为 62 个文件，只有 HdrClamper 系（7 个 smali），
无 HdrBrightnessModifier；366 两者都有。

### 4）354 的 HdrClamper 与 331 是否一致？——**完全一致（逐字节）**

HdrClamper.smali 及全部内部类/Lambda 共 7 文件 md5 相同。

但差异全部落在行号偏移、版本字符串与联想私有段（DPC 的 brightness_hdr 重构、ZuiDisplayService 白名单扩充），

## 四、结论

**354 与 331 的上游 HDR 显示链（LocalDisplayAdapter 全家、DisplayDeviceConfig、clamper 全目录）逐字节一致；
354 可作为 A15 正常基线的等价物。** 354 相对 331 的 services.jar 变化仅限：
1. DPC 内联想 `persist.sys.brightness_hdr` 写入逻辑重构（含游戏性能模式禁 HDR 亮度）；
2. ZuiDisplayService 联想私有的 HDR 状态机/白名单小重构（新增图库与 Pattern 包名）；
3. 其余为行号与日志字符串漂移。

这反证 366 的 UltraHDR 失效根因（handleHdrSdrNitsChanged 门③ + hasSdrToHdrRatioSpline 改读
mHbmData.sdrToHdrRatioSpline + HdrBrightnessModifier 新增）全部是 A16（366）才引入的回归点，与 354 无关。
