### 1. 版本史过曝程度演变(重要!)
| 时代 | ratio 策略 | 过曝表现 |
|---|---|---|
| v6+GPU合成 | 定值/公式(实读≈1.734 或冻结 1.6089) | **30% 正常、高亮过曝**;"过曝只剩一丝" |

→ 过曝程度与 **ratio 值正相关**(v1.1.8 低亮度 ratio 3.97 最过曝)。这支持"渲染域钳白"假说 H1(见下)。

### 3. 假说集(按当前概率)
- **H1 渲染域钳白(高)**:hwui/App 在 SDR 输出路径应用 gainmap boost(=ratio),高光值>1 被钳白 = 过曝。ratio 越大越严重(与版本史吻合)。A15 正常是因为 hwui 走 HDR 层路径(FP16+SF tone map),高光不钳。366 上 hwui 输出层是否 HDR 层取决于某条件(window colorMode? display HDR 支持? desiredHdrSdrRatio?)
- **H2 亮度域不匹配(中)**:DPC 抬亮(HdrBrightnessModifier)倍数≠App ratio,SDR dimming 错位。dumpsys 有 temporary[hdr] 事件暗示抬亮链活动
- **H3 双重 boost(中)**:hwui shader boost + SF/DPU tonemap boost 叠加
- **H4 动态 ratio 振荡(中低)**:F 写口 ratio 随 mCurrentNits 变,DPC 抬亮→nits↑→ratio↓→振荡(v1.1.8 任何亮度都过曝不太像振荡,振荡更该表现为闪)

### 4. A15 闭环自洽模型(理论,待 B 证实公式)
```
无HDR层: brightness=B, sdrBrightness=B → nits=N, sdrNits=N → ratio=1 → W=0
HDR层出现: SF聚合desiredHdrSdrRatio=D → 上报DPC
  → DPC: 目标hdrBrightness = getHdrBrightnessFromSdr(B, D, spline) → 抬亮
  → sdrBrightness 通道压暗(B/ratio) → setDisplayBrightness(B', B/ratio)
  → LocalDisplay: nits=N'(=spline(N)×N), sdrNits=N
  → handleHdrSdrNitsChanged: ratio = N'/N = spline(N) ←闭环!
  → App 读 ratio = 面板实际 headroom,精确同步
```
关键:**A15 的 ratio 是"结果"(DPC 抬亮行为的读出),不是"原因"**。模块的 F 写口把 ratio 当"原因"先给 App,若 DPC 抬亮链不配合,App 白拿 boost → H1 钳白过曝。
